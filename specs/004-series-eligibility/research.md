Alle neun gebundenen Intake-Befehle bestehen lokal auf macOS. / **Rationale:** The existing series validator checks normalized hashes, proven lifecycle resolution, target order, directed edges, roots, and at most one declared Eligible. The sequencing suite tests both shells and rejects the named failures. All nine bound intake commands pass locally on macOS.

Der kleine `specs/intake-review-fixtures/meta-lh-04/validate-series-eligibility.py` prüft die Schlüsselmenge, Modi und sechs Parallelflags. Er prüft keine Kriterienwerte, nutzt Wahrheitswerte statt strikter Booleans und verliert doppelte JSON-Schlüssel beim Einlesen. Drei temporäre Proben ergeben jeweils Exit 0 und `Eligible`: `integration=""`, `currentAuthority="false"` und ein doppelter `authority`-Schlüssel. [Ausgeführte Recherchebelege](phase-results/plan-baseline.json) dokumentieren die Proben. Die Proben ändern nur temporäre Dateien. / *The small fixture validator checks key sets, modes, and six parallel flags. It does not check criterion values, uses truthiness instead of strict booleans, and loses duplicate JSON keys while loading. Three temporary probes each return exit zero and Eligible: empty integration, string-valued authority, and duplicate authority. The linked evidence records these probes; only temporary files were changed.*

**Alternativen:** Eine neue Graph-Engine oder ein Produkt-CLI würde bereits erfüllte Arbeit duplizieren. Den alten Prüfer direkt zu ändern wäre kleiner im Code, aber größer in der Evidence-Wirkung; R2 begründet die additive Grenze. / **Alternatives:** A new graph engine or product CLI would duplicate satisfied work. ## R3 – Status und Next bleiben Abfragen / Status and next remain queries

**Entscheidung:** Bestehende `speckit.intake-series-status.md` und `speckit.intake-series-next.md` als Bedienvertrag verwenden; die neue Feature-Prüfung liefert dazu reproduzierbare Projektionen. / **Decision:** Use the existing status/next command documents as the usage contract; the feature checker supplies reproducible projections for their verification.

**Begründung:** Diese Oberflächen sind Agenten-Anweisungen, keine eigenständigen ausführbaren CLI-Programme. Sie verlangen Vorher-/Nachher-Hashes, getrennte Zustände und keinen Start. Der vorhandene JSON-Summary enthält `eligible` und `declaredEligible`, aber keine vollständigen DE/EN-Gründe oder Failure-Taxonomie. Mehrere berechnete Kandidaten sind zulässig; mehrere *deklarierte* Eligible-Mitglieder sind ungültig. Ein bevorzugter Kandidat wird nur aus `declaredEligible` übernommen; ohne Präferenz werden alle berechneten Kandidaten in Manifestreihenfolge angezeigt. Genau eine sichere nächste Aktion fordert die menschliche Auswahl bzw. Prüfung an. Es wird kein Kandidat erfunden. / **Rationale:** These surfaces are agent instructions, not standalone CLI programs. They require before/after hashes, separate states, and no start. Existing JSON summaries expose eligible and declaredEligible but lack complete bilingual reasons and failure classification. Multiple calculated candidates can be valid; multiple declared Eligible members are invalid. A preferred candidate comes only from declaredEligible; without a preference, all calculated candidates remain visible in order. Exactly one safe next action asks for human selection or review. No candidate is invented.

**Alternativen:** Die generischen Agentenflächen umzuschreiben wäre nicht nötig. Die Feature-Projektion beweist die deterministische Datenverarbeitung; ein separates semantisches Review prüft die tatsächliche Agentenausgabe und ihre Nicht-Autorität. / **Alternatives:** Rewriting generic agent surfaces is unnecessary. The projection proves deterministic data handling; a separate semantic review assesses actual agent output and its non-authority.
